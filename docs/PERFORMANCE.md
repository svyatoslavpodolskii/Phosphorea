# Проверка производительности карты

`npm run build`, затем `npx playwright test --config tests/performance.config.ts`.
Для карты с 5000 атомами задайте `PERF_LARGE=1`. `PERF_LABEL` задаёт префикс
JSON-отчёта в `artifacts/performance/`. Эти результаты не отправляются в сеть.

Проверка импортирует реальные атомы и связи, ждёт непустую отрисованную сцену,
меняет масштаб 100 кадров и записывает интервалы requestAnimationFrame и время
работы рендера. Атомы закреплены: тест измеряет камеру, отдельно от физики.
За пределами экрана работает отсечение; число атомов в карте не равно числу
видимых одновременно рисунков. Размер окна — 1280×800.

В Chromium CPU искусственно замедлен в 4 раза, используется Canvas при отсутствии
аппаратного WebGL. Firefox запускается без замедления CPU, с доступным WebGL.
Они не сравниваются между собой как одинаковое железо.

## Сопоставимый прогон 0.9.4 → 0.9.5

Медианный интервал кадров, миллисекунды; тестовый компьютер, без параллельной нагрузки:

| Браузер | Атомов | До | После |
| --- | ---: | ---: | ---: |
| Chromium, CPU ×4, Canvas | 20 | 40.8 | 24.3 |
| Chromium, CPU ×4, Canvas | 1000 | 63.2 | 53.1 |
| Firefox, WebGL | 20 | 108.7 | 13.3 |
| Firefox, WebGL | 1000 | 114.5 | 13.8 |

Контрольная сборка с 5000 реально отображаемыми атомами: Firefox — медиана
13.5 мс, 95-й процентиль 24.8 мс; Chromium с CPU ×4 и Canvas — 72.4 и 85.4 мс.
Пустая проекция не считается успешным прогоном: тест дожидается непустой сцены.

Слабый Canvas-путь всё ещё может выходить за бюджет 16.7 мс. Реальный Nothing Phone 1
в этих замерах не участвовал. Для него нужны замеры на устройстве, особенно для
больших карт в движении и параллакса; эмуляция окна не заменяет мобильный GPU.

## Найденные причины

Контроль 0.9.6 (тот же сценарий, настольные браузеры):

| Режим | Атомы | Медиана кадра, мс | p95, мс |
| --- | ---: | ---: | ---: |
| Chromium, Canvas, CPU ×4 | 20 | 19.0 | 28.2 |
| Chromium, Canvas, CPU ×4 | 1000 | 47.2 | 62.5 |
| Firefox, WebGL | 20 | 13.2 | 15.9 |
| Firefox, WebGL | 1000 | 13.7 | 27.1 |

Кривые связей теперь переиспользуются, пока не изменились координаты или радиусы
концов. Кеш текста увеличен до 16384 записей: 5000 разных названий больше не
вытесняют друг друга при последовательном обходе. Эти изменения не означают,
что Canvas на слабом устройстве держит 60 кадров в секунду.

- SVG-фон с фильтрами и patternTransform вызывал полную перерисовку вне JavaScript.
  Теперь статичный рисунок однократный, а движущийся фон использует ограниченные
  по памяти плоскости с transform.
- На каждом шаге камеры повторялись подготовка спокойной сцены, сортировка,
  обход невидимых спутников, подсчёт внимания и границ. Результаты переиспользуются.
- Canvas повторно рисовал контуры, градиенты, значки и подписи. Рисунки кешируются
  в атласе с ограничением 32 МиБ.
- Рекурсивные обходы длинных цепочек могли ломать проекцию. Построение размеров,
  списка потомков и группировка переведены на итеративный обход.
